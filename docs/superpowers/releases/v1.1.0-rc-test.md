**Measured fps:** steady state 60-62 (25+/30 samples); warm 30s re-sample
min 60 / max 63 (floor 45).
**Soak:** 10 min, engine alive, same pid (23561), frames advancing.

**WAIVED — `fps floor`, operator-accepted 2026-07-27.** A real, reproducible
~1-2s stall shortly after quest start drops one sample to 0 fps. Confirmed NOT
a measurement-window artifact: tightening the readiness poll from "2 consecutive
samples >= floor" to "engine's own `Simulation started` + 5 consecutive samples"
moved the 0 from sample 4 to sample 1 rather than removing it — i.e. the stall
occurs at a roughly fixed time after quest start, so delaying the window just
slides it over the same event.

**Cause (operator, 2026-07-27):** the title screen's display surface being
attached to the FPGA offload. That is a one-time cost at that transition, which
is exactly the measured shape — a single ~1-2s drop at a fixed point after quest
start, once, then a flat 60-62 for the rest of the run. Known issue, not a
v1.1.0 regression.

The check was deliberately left FAILING rather than loosened, so it fails again
on the next RC and must be re-accepted with fresh eyes. If it is worth making
the gate tolerate this specifically, the principled way is to key readiness off
the surface-attach completing (engine truth), not to widen the floor or the
window — the two attempts recorded above show that moving the window just slides
it over the same event.

**Master_Daemon:** stopped by Gate 2, not restarted (device needs a reboot to
get it back, or leave the Solarus daemon running via `Scripts/Solarus.sh`).

## Harness defects found and fixed during this run

| # | Defect | Symptom | Fix |
|---|---|---|---|
| 1 | Launch `RSH` held the ssh channel's stdout/stderr | Gate 2 hung forever at "launching engine" — no rows, no timeout, indistinguishable from the documented 12-min soak | Release the remote shell's fds before backgrounding; command text moved to `rc_launch_cmd()` with regression tests T43/T43b (`6472631`) |
| 2 | fps readiness fired during preload | Strict-minimum window opened before startup ended | Gate on engine-truth `Simulation started` + 5 steady samples; floor unchanged (`e7dcae7`). Did NOT fix the FAIL — see the waiver above |
| 3 | `RSH` had no ssh keepalive | Preflight sat 8+ min on a half-open socket: host `ESTABLISHED`, no sshd on device | `ServerAliveInterval=15` / `CountMax=4`; drops now fail closed in ~60s (`165a5ed`) |

Defects 1 and 3 share a root pattern: **Gate 2 had no bounded failure mode for
device I/O**, and because the recipe tells operators to expect a 12+ minute
block, every hang was camouflaged as a normal soak. Neither was reachable by
the host suite or by code review — 1 needed a real ssh channel, 3 needed a real
network drop.

Also added: `release_test.sh waive` (`28a6bc5`), so accepting a known failure is
a recorded act with a reason rather than a quiet loosening of a check.
